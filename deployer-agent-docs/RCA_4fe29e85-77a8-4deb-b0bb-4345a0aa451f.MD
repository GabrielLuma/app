# RCA — "site não está no ar" (Glas Park / arte-vidreiros)

## Problem statement
User reported the site appears down ("aqui pra mim diz q o site nao esta no ar"). A "Deployment initiated" async notification was seen earlier, with no completion/URL confirmation.

## Investigation & evidence
- `describe_deployment_state`: deployment_status = **active**; active_run_id `4fe29e85-77a8-4deb-b0bb-4345a0aa451f` (type=redeploy, trigger=secret_change) status = **success**, completed_at 2026-10-01T22:22:01Z. The earlier "initiated" notification corresponds to this run — it finished successfully.
- `preview_health_check` on `https://arte-vidreiros.emergent.host/`: **HTTP 200**, 635ms, body is the real Glas Park app HTML (title "GLAS PARK — Museu do Cristal · Blumenau"). Not the nginx default page.
- `list_domains`: `glaspark.com.br` and `www.glaspark.com.br` both verified=true, ssl_status=**active**, provider=cloudflare.
- `check_domain_status`: both domains **linked=true** (DNS A-records resolve to us).

## Root cause
**No production outage.** The pipeline completed successfully, the default URL serves the correct app with 200, and both custom domains are verified with active SSL and resolving DNS. The "not up" report is client-side — most likely stale browser/DNS cache, viewing during the brief deploy/promote window, or a local network issue.

## Recommended actions
- User: hard-refresh / open in incognito, or test from another network/device. Confirm which URL is being used (default vs glaspark.com.br).
- If still failing for the user, capture the exact error/status shown and the failing request in DevTools so we can diagnose the client path.
